# Releasing

`ftop` ships as a Homebrew cask generated by GoReleaser. A tag is all it takes:

```bash
git tag v0.3.0
git push origin v0.3.0
```

GitHub Actions then runs `make probe`, cross-compiles ftop for darwin and linux
(both arm64 and amd64), signs and notarizes the macOS binaries, uploads the
archives to a GitHub release, and writes `Casks/ftop.rb` into
`To1and/homebrew-tap`. Users install with:

```bash
brew install To1and/tap/ftop
```

The tap has to be named: Homebrew refuses to load a cask from a third-party tap
until it is trusted, and a fully qualified install trusts that cask, so
`brew tap To1and/tap && brew install ftop` stops at the trust check. `--cask`
is not needed because the tap has no formula called ftop.

## The two-step build

The probe is a linux/amd64 binary embedded into the TUI with `//go:embed`, and
it is gitignored. GoReleaser's `before.hooks` runs `make probe` first; every
build then compiles with `-tags probe` so the embed resolves. The probe is
always linux/amd64 regardless of the target platform — that is the platform of
the machines being watched, not of the machine running ftop.

## One-time setup

### 1. Repositories

`To1and/ftop` and `To1and/homebrew-tap` both exist and are public; brew must be
able to read the tap and download the release without credentials. GoReleaser
writes `Casks/ftop.rb` into the tap's `main` branch on every release.

The tap is written over ssh with a deploy key (write access to that one
repository only, no expiry). Its private half is the `TAP_DEPLOY_KEY` secret.
To replace it:

```bash
ssh-keygen -t ed25519 -N "" -C "ftop release" -f /tmp/tap_key
gh repo deploy-key add /tmp/tap_key.pub -R To1and/homebrew-tap --allow-write -t "ftop release"
gh secret set TAP_DEPLOY_KEY -R To1and/ftop < /tmp/tap_key
rm /tmp/tap_key /tmp/tap_key.pub
```

### 2. Developer ID certificate

The Apple Development certificate cannot sign software distributed outside the
App Store. You need a **Developer ID Application** certificate; only the
account holder can create one:

- Xcode → Settings → Accounts → Manage Certificates → `+` → *Developer ID
  Application*, or
- developer.apple.com → Certificates, Identifiers & Profiles → `+` →
  *Developer ID Application*.

Then export it from Keychain Access (My Certificates → the certificate, with its
private key → Export) as a password-protected `.p12`.

### 3. App Store Connect API key

App Store Connect → Users and Access → Integrations → App Store Connect API →
Team Keys → generate a key with the *Developer* role. Download the `.p8` once
(Apple does not let you download it again), and note the key ID (it is in the
`.p8` filename) and the issuer ID (a UUID shown above the key list).

### 4. Secrets

In `To1and/ftop` → Settings → Secrets and variables → Actions, or with `gh`:

```bash
base64 -i Certificates.p12 | gh secret set MACOS_SIGN_P12 -R To1and/ftop
gh secret set MACOS_SIGN_PASSWORD -R To1and/ftop        # prompts for the .p12 password
base64 -i AuthKey_XXXXXXXXXX.p8 | gh secret set MACOS_NOTARY_KEY -R To1and/ftop
gh secret set MACOS_NOTARY_KEY_ID -R To1and/ftop -b XXXXXXXXXX
gh secret set MACOS_NOTARY_ISSUER_ID -R To1and/ftop     # prompts for the issuer UUID
```

| Secret | Value |
| --- | --- |
| `MACOS_SIGN_P12` | base64 of `Certificates.p12` |
| `MACOS_SIGN_PASSWORD` | the `.p12` password |
| `MACOS_NOTARY_KEY` | base64 of the `.p8` |
| `MACOS_NOTARY_KEY_ID` | the 10-character key ID |
| `MACOS_NOTARY_ISSUER_ID` | the issuer UUID |
| `TAP_DEPLOY_KEY` | private half of the tap's deploy key (see 1) |

`GITHUB_TOKEN` is supplied by Actions and can only write the repository running
the workflow, so writing the tap needs its own credential.

An unsigned binary installed by a cask is quarantined and macOS refuses to run
it, so a release must not go out without the five `MACOS_*` secrets. With them
set, the release waits until Apple has accepted the notarization.

## Local dry run

```bash
goreleaser release --snapshot --clean
```

Signing and notarization run whenever `MACOS_SIGN_P12` is set, so with the
secrets exported a snapshot produces four signed, notarized archives and a cask
under `dist/` — everything except the upload and the tap commit. Without them it
builds four unsigned archives, which is enough for the layout but proves nothing
about Gatekeeper.

The same run is available on CI: *Actions → release → Run workflow* with
`snapshot` left on. It exercises the real secrets the way a tag will, and
publishes nothing.

## Version

`cmd/ftop/main.go` has `var version = "dev"`, overwritten at link time with
`-X main.version={{ .Version }}` from the tag. `ftop --version` prints the tag
without the leading `v`. The `VERSION ?= 0.3.0` default in the Makefile only
affects local `make` builds.

## If the cask replaces an older formula

If `To1and/homebrew-tap` ever carried a `Formula/ftop.rb`, add
`tap_migrations.json` (`{"ftop": "ftop"}`) and delete the formula; otherwise
`brew install ftop` resolves to the stale formula. Existing formula users need
`brew uninstall ftop && brew install --cask ftop`.
